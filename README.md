## 1. Claude 기반 간호사 스케줄링 MCP

**전문 최적화 엔진을 대화로 활용할 수 있도록 연결한 프로젝트**

- **수행 맥락:** Omelet 연구 인턴십 중 수행한 스케줄링 PoC
- **주요 개발 기간:** 2025.07–2025.08
- **담당:** 초기 MCP 연동, 설정 처리, 결과 비교·데이터 질의 기능 구현 및 개선

### 문제

근무표를 자동 생성하는 최적화 엔진이 있어도, 현업 사용자가 직접 코드를 실행하고
설정값을 바꾸며 결과를 해석하기에는 사용 장벽이 있었습니다.
생성 조건을 조정하고, 결과를 확인한 뒤 다시 계산하는 과정을 하나의 사용 흐름으로 연결하고자 했습니다.

### 구현과 기여

- 초기 FastMCP 서버와 입력 검증·근무표 생성·요약 도구를 구현하고, 기존 최적화 엔진의 호출 흐름에 연결했습니다.
- 생성 도구에 가중치와 제약 기준을 전달하고, 기본값과 현재 설정의 병합을 통해 설정 누락을 보완했습니다.
- 생성 결과의 비교 기능과 근무표를 pandas DataFrame으로 변환하는 데이터 질의 기능을 추가했습니다.
- 입력에서 읽은 근무코드 정보를 캐시해 질의 결과를 해석할 수 있도록 개선했습니다.

### 설계에서 중요하게 본 점

Claude는 사용자 요청을 해석하고 필요한 도구를 선택하며, 실제 근무 배정은 기존 CP-SAT 엔진이 계산하도록
역할을 나눴습니다. 또한 결과 ID와 사용한 설정을 함께 관리해 조건 변경 후 재생성과 결과 비교를 연결했습니다.

```text
사용자 요청 → Claude의 MCP 도구 호출 → 입력·설정 처리 → 기존 최적화 엔진
                                                        ↓
파일 출력 ← 결과 분석·비교 ← 결과 ID와 설정 보관 ← 생성 결과
```

### 결과와 범위

설정 조회·변경, 근무표 생성, 분석·비교, 추가 질의와 파일 출력을 지원하는 로컬 데모를 구현했습니다.
최종 검토 버전에는 16개 MCP 도구가 등록되어 있습니다.
팀원이 수행한 서버 구조 개편과 함께 발전시킨 프로젝트이며, 위 항목은 제가 구현·개선한 기능을 중심으로 정리했습니다.

공개 저장소에는 프로젝트 설명과 구조도·사용 시나리오를 담았습니다.
회사 소스코드와 실제 병원 데이터는 포함하지 않으며, MCP 데모의 상용 도입이나 정량적인 업무 개선 효과를 주장하지 않습니다.

## 2. 스마트 횡단보도

**보행자 인식과 이동 속도 추정을 신호 연장 시간 계산으로 연결한 시스템**

- **기간:** 2024.01–2024.02
- **프로젝트 형태:** Ambient AI 팀 프로젝트
- **성과:** 서울대학교 데이터사이언스대학원 주최 Ambient AI 경진대회 2위

### 문제

보행 속도가 느린 사람이 횡단 중일 때, 정해진 녹색 신호 시간만으로는 필요한 이동 시간을 충분히 반영하기 어렵습니다.
영상에서 보행자의 위치와 움직임을 추적하고, 남은 거리와 신호 시간을 비교해 추가 횡단 시간을 계산하고자 했습니다.

### 구현과 기여

- YOLOv8 기반 보행자 인식과 추적 결과를 활용해, 보행자를 지속적으로 관측하는 분석 흐름을 구현했습니다.
- 영상 인식 결과와 보행 속도 추정을 연결하고, 남은 횡단 거리와 녹색 신호 시간을 바탕으로 신호 연장 시간을 계산하는 로직을 구현했습니다.

### 시스템 흐름

```text
영상 입력 → 보행자 탐지·추적 → 보행 보조기구 분류
                  ↓                    ↓
          지면 좌표·속도 추정 → 추가 횡단 시간 계산
```

바운딩 박스 하단 중심을 지면 좌표로 변환하고, 시간에 따른 위치 변화로 이동 속도를 추정합니다.
보행 보조기구 관련 분류 결과와 이동 속도를 함께 사용해 판단 대상 경로를 선정한 뒤,
남은 거리를 이동하는 데 필요한 시간과 녹색 신호 잔여 시간을 비교합니다.

### 결과와 범위

Ambient AI 경진대회에서 2위를 기록했습니다.
공개 저장소에는 영상 처리·추적·분류·좌표 변환·속도 추정·시간 계산을 분리한 코드와 실행 안내를 제공합니다.

현재 저장소의 로직 검증에는 가상 경로와 모델 대역을 사용한 38개 테스트가 포함되어 있습니다.
정리 과정에서 원본 모델·영상을 다시 실행해 정확도나 실시간 처리 성능을 재측정하지는 않았으며,
실제 교통 신호 제어기와의 연동은 구현 범위에 포함하지 않습니다.

## 3. OGC 차량 적재 최적화

**목적 항구와 경로 접근성을 함께 고려한 선적·하역 휴리스틱**

- **기간:** 2025.07–2025.08
- **프로젝트 형태:** Optimization Grand Challenge 팀 프로젝트
- **성과:** 전국 343팀 중 17위

### 문제

차량운반선이 여러 항구를 차례로 방문할 때, 먼저 내려야 할 차량 앞을 다른 차량이 막으면
선내 재배치나 반출 후 재선적이 필요합니다. 현재 항구의 적재 공간을 채우면서도
이후 항구에서 차량을 꺼낼 수 있는 배치와 이동 경로를 찾아야 했습니다.

### 구현과 기여

- 선박 내부를 NetworkX 그래프로 표현하고, BFS·DFS 기반 접근성 판단을 선적 위치와 이동 경로 선택에 활용했습니다.
- 목적 항구 순서와 인접 차량의 도착 항구를 고려하는 배치 로직, 선적·하역 및 방해 차량 재배치 휴리스틱을 구현·개선했습니다.
- 항구별 남은 최소 이동 비용을 계산하고, 현재 최선의 해를 개선할 수 없는 구성 시도를 조기에 중단하도록 했습니다.
- 간선 셔플과 탐색 순서를 달리하는 반복 탐색을 멀티프로세싱으로 실행해, 제한된 시간 안에서 더 낮은 비용의 해를 찾도록 구성했습니다.

### 설계에서 중요하게 본 점

선박의 빈 공간뿐 아니라 **차량을 이동시킬 수 있는 경로가 남아 있는지**를 배치 판단에 반영했습니다.
목적 항구별 접근성과 남은 적재 공간을 함께 평가하고, 하역 시에는 방해 차량의 선내 이동과 반출을 검토했습니다.

비용은 각 이동 경로의 고정 비용과 이동 거리의 합으로 계산합니다.
실행 가능성을 검증한 뒤 대회 기준 하한 비용을 뺀 평가값으로 결과를 비교합니다.

### 결과와 검증

대회에서 전국 343팀 중 17위를 기록했습니다.
현재 공개 코드에서는 선적·하역·배치·경로 탐색·병렬 실행을 모듈로 구분하고 실행·검증 명령을 제공합니다.

코드 정리 후에는 동일한 난수 조건에서 **공개 예제 20개 모두가 제출 당시 코드와 같은 경로·비용을 생성하는지** 확인했습니다.
이는 구현의 동작 보존을 확인한 검증이며, 대회 순위나 장시간 병렬 탐색 성능을 재측정한 결과는 아닙니다.
